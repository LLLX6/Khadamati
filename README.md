# خدماتي | Khadamati App

## الإصدار v1.1.1

منصة عُمانية ثنائية اللغة تربط طالب الخدمة بالمزود أو الشركة، وتدير الطلب والعروض والمحادثة والاشتراك من واجهة مهيأة للهاتف أولًا.

## ما يتضمنه V1

- رحلة طلب واضحة: القسم، الخدمة الدقيقة، الموقع، التفاصيل، ثم المراجعة.
- مطابقة دقيقة حسب الخدمة والمنطقة والتوفر وحالة الحساب والاشتراك.
- ملف خدمة واحد ينتقل بين: جديد، انتظار العروض، اختيار المزود، تنسيق الموعد، التنفيذ، ثم الإكمال أو الإلغاء.
- صفحة مستقلة للمحادثات، وإشعارات مجمعة تفتح السجل المقصود مباشرة.
- موافقة مستقلة قبل إظهار الاتصال أو واتساب لكل طلب ومزود وقناة.
- مساحة مزود منظمة: اليوم، الفرص، المهام الجارية، والحساب.
- مركز إدارة للقرارات والمزودين والاشتراكات والمال والجودة والتقارير.
- خمس باقات فقط، مع فترة سماح وتنبيهات انتهاء وسجل تدقيق إداري.
- خريطة تفاعلية مبنية على Leaflet وOpenStreetMap دون مفتاح سري.
- مجتمع موحد بثلاث مساحات: باقات المزودين، «أبحث عن» للمستخدمين، وساحة الطلبات المطابقة.
- نشر باقات بخطط وحدود قابلة للتحكم من الإدارة، وعروض على احتياجات المستخدم تنشئ طلبًا ومحادثة فعلية عند القبول.
- بحث وتصنيف ومفضلة وبلاغات وإشراف وانتهاء تلقائي وإشعارات وروابط مباشرة لكل عنصر في المجتمع.
- سياسات عربية وإنجليزية، ووضعان فاتح وداكن، ودعم RTL وLTR.

## بنية المشروع

| الجزء | التقنية |
|---|---|
| الواجهة | PWA في `index.html`، ونسخة نشر مطابقة في `public/index.html` |
| التصميم | نظام موحد في `assets/styles/khadamati-v1.css` |
| الرسوم | `assets/scripts/khadamati-visuals.js` |
| الخادم | Python في `server.py` |
| منطق النطاق | `khadamati_domain.py` و`khadamati_workflow.py` |
| قاعدة البيانات | SQLite افتراضيًا، مع مخطط PostgreSQL مرجعي للتوسع |
| التخزين المحلي | تفضيلات وكاش انتقال فقط؛ الخادم هو مصدر الحقيقة للحسابات والطلبات |
| النشر | GitHub Pages للواجهة وRender لخادم API |

## الأدوار

- `user`: يطلب الخدمة ويتابع العروض والمحادثة والتنفيذ.
- `provider`: مزود فردي داخل مجال أساسي واحد وخدمات فرعية تسمح بها باقته.
- `provider_owner`, `provider_manager`, `provider_staff`: أدوار فرق الشركات.
- `admin`, `super_admin`: مراجعة وتشغيل وقرارات إدارية بتحقق خادمي.
- `guest`: تصفح معزول لا يرى جلسات أو إشعارات الحسابات المحفوظة.

## دورة الطلب

```text
جديد
  -> بانتظار العروض
  -> اختيار المزود
  -> تنسيق الموعد
  -> جاري التنفيذ
  -> مكتمل أو ملغي
```

لا تبقى أزرار المقارنة أو تقديم عرض جديد بعد قبول المزود. كل انتقال يسجل وقتًا وحالة، وتمنع مفاتيح idempotency تكرار الطلب عند الضغط المتكرر أو ضعف الشبكة.

## الباقات

العملة `OMR`، والأسعار والصلاحيات قابلة للتعديل من الإدارة.

| المفتاح | المدة | السعر | الاستجابات والتأخير |
|---|---:|---:|---|
| `foundation_12m` | 12 شهرًا | 0 | 30 شهريًا، بعد 15 دقيقة |
| `basic_6m` | 6 أشهر | 6 | 60 شهريًا، بعد 10 دقائق |
| `basic_12m` | 12 شهرًا | 10 | 60 شهريًا، بعد 10 دقائق |
| `professional_12m` | 12 شهرًا | 20 | 150 شهريًا، فوري |
| `business_12m` | 12 شهرًا | 40 | فوري، فريق وفروع وصندوق مشترك |

المزود الفردي يبقى داخل مجال أساسي واحد، بينما تسمح باقات الشركات بعدة مجالات وخدمات. الخادم يعيد التحقق من الحدود ولا يعتمد على إخفاء الخيارات في الواجهة.

## التشغيل المحلي

يتطلب Python 3.11 أو أحدث وNode.js لتشغيل اختبارات الواجهة.

```powershell
Copy-Item .env.example .env
$env:KHADAMATI_ENV="development"
$env:KHADAMATI_DEV_ADMIN_CODE="رمز-محلي-قوي"
$env:KHADAMATI_DEV_OTP_CODE="رمز-اختبار"
python server.py
```

ثم افتح:

```text
http://127.0.0.1:8080
```

يمكن أيضًا تشغيل `start-khadamati-app.bat` على Windows.

## متغيرات البيئة

استخدم `.env.example` مرجعًا، ولا ترفع `.env` إلى Git.

| المتغير | الغرض |
|---|---|
| `KHADAMATI_ENV` | `development` أو `test` أو `production` |
| `KHADAMATI_RELEASE` | رقم الإصدار، حاليًا `v1.1.1` |
| `KHADAMATI_PUBLIC_URL` | رابط الواجهة العامة |
| `KHADAMATI_ALLOWED_ORIGINS` | قائمة CORS المسموحة |
| `KHADAMATI_DB_PATH` | مسار قاعدة SQLite الدائم |
| `KHADAMATI_UPLOAD_DIR` | مسار رفع الصور والوثائق الدائم |
| `KHADAMATI_BACKUP_DIR` | مسار النسخ الاحتياطية |
| `KHADAMATI_ADMIN_CODE` | رمز تأسيس الإدارة، ولا يظهر في الواجهة |
| `KHADAMATI_OTP_PEPPER` | سر تجزئة رموز التحقق |
| `KHADAMATI_MEDIA_SIGNING_KEY` | سر توقيع روابط الوسائط الخاصة |
| `KHADAMATI_SUPPORT_EMAIL` | البريد المركزي، افتراضيًا `om.khadamati@gmail.com` |
| `KHADAMATI_PAYMENT_*` | إعداد بوابة الدفع وWebhook |
| `WHATSAPP_*` | WhatsApp Cloud API الاختياري |
| `VAPID_*` | مفاتيح Web Push الاختيارية |

لا يصبح الدفع أو OTP إنتاجيًا بمجرد ظهور الواجهة. عند غياب مفاتيح صحيحة تبقى العملية بانتظار التحقق أو موافقة الإدارة، ولا يعرض التطبيق نجاحًا وهميًا.

## البيانات والترحيل

- يعمل ترحيل الاشتراكات مرة واحدة بالمفتاح `KHADAMATI_SUBSCRIPTION_MIGRATION_V1`.
- تُعطّل الخطط القديمة بدل حذف السجلات المالية أو الاشتراكات.
- لا تحذف الحسابات أو المحادثات عند انتهاء الاشتراك؛ يتوقف الظهور واستقبال الطلبات فقط.
- تحتفظ تحديثات الحدود بخدمات المزود القديمة، وتمنع زيادة التجاوز حتى يعود الحساب داخل الحد.

أنشئ نسخة احتياطية:

```powershell
python scripts/backup_sqlite.py --database khadamati.sqlite3 --uploads public/uploads --output backups/khadamati-backup.zip
```

اختبر الاستعادة إلى مسارات فارغة:

```powershell
python scripts/restore_sqlite_backup.py --archive backups/khadamati-backup.zip --database-target restored/khadamati.sqlite3 --uploads-target restored/uploads --confirm RESTORE_TO_EMPTY_TARGET
```

## الأمان

- المصادقة والصلاحيات وملكية السجلات تتحقق في الخادم.
- رموز الدخول مجزأة ولا تُعرض للإدارة.
- روابط الوثائق والوسائط الخاصة موقعة ومحدودة العمر.
- رفع الملفات يتحقق من MIME والتوقيع والحجم والاسم الآمن.
- توجد حدود محاولات للدخول وOTP والطلبات الحساسة.
- وثائق المزود خاصة بالإدارة المخولة.
- سجل التدقيق يحفظ القرارات المالية والإدارية الحساسة.
- لا تمنح الباقة المدفوعة حق شراء بيانات العملاء.

## النشر

- GitHub Pages يقدم الواجهة وService Worker.
- Render يشغّل API وقاعدة البيانات ورفع الملفات.
- يجب أن تكون قاعدة البيانات والملفات على تخزين دائم قبل استقبال مستخدمين حقيقيين.
- القرص المؤقت في أي منصة استضافة غير مناسب لحسابات وطلبات الإنتاج.
- يجب ضبط Health Check على `/healthz`، ويمكن فحص الجاهزية عبر `/readyz`.

فحص إعدادات الإنتاج:

```powershell
python scripts/check_production_readiness.py
```
