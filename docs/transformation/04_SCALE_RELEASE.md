# المرحلة الرابعة: التوسع والامتثال والإطلاق

**تاريخ التحقق الرسمي:** 1 أغسطس 2026

## ما جُهز تقنيًا

- Payment Adapter خادمي يدعم التحقق وIdempotency ووضع الموافقة اليدوية، دون ادعاء وجود بوابة دفع حية.
- Adapters قابلة للاستبدال للتأمين والتكامل الحكومي، معطلة افتراضيًا حتى وجود عقد وAPI رسميين.
- مساعد طلب حتمي ومنظم لا يرسل وصف المستخدم إلى نموذج خارجي.
- Risk Review يسجل الإشارات ويرسلها لمراجعة بشرية ولا يحظر المستخدم آليًا.
- Enterprise API بمفاتيح مجزأة ونطاقات وحدود طلب وسجل تدقيق.
- Feature Flags، Health/Readiness، Structured Logging، CI، Backup/Restore وRollback موثق.
- مخطط PostgreSQL جاهز للانتقال الإضافي، مع بقاء تشغيل SQLite للتطوير وعدم الادعاء بأنه مناسب للتوسع الكبير.

## تحقق Apple وGoogle

المصادر الرسمية التي تمت مراجعتها في 1 أغسطس 2026:

- [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/): التطبيق الذي يسمح بإنشاء حساب يجب أن يتيح حذف الحساب من داخله، ويجب إزالة المحتوى المؤقت قبل الإرسال.
- [Apple: Offering account deletion](https://developer.apple.com/support/offering-account-deletion-in-your-app/): التعطيل المؤقت وحده لا يكفي؛ يجب إتاحة حذف الحساب والبيانات المرتبطة مع توضيح ما يلزم الاحتفاظ به قانونيًا.
- [Google Play account deletion requirements](https://support.google.com/googleplay/android-developer/answer/13327111): يلزم مسار حذف داخل التطبيق ورابط ويب يستطيع المستخدم من خلاله طلب حذف الحساب والبيانات.
- [Google Play Data safety](https://support.google.com/googleplay/android-developer/answer/10787469): يجب التصريح بدقة عن جمع البيانات ومشاركتها وأمانها، بما في ذلك ممارسات مكتبات الطرف الثالث.

المسارات والمستندات جُهزت داخل `ملفات-الإطلاق/06-متطلبات-المتاجر/` و`07-السياسات-والاتفاقيات/`، لكن قبول المتجر لا يمكن ضمانه قبل بناء الحزمة وتوقيعها ومراجعتها في الحساب الرسمي.

## تحقق سلطنة عُمان

- [اللوائح التنفيذية لقانون حماية البيانات الشخصية، القرار 34/2024](https://www.ita.gov.om/itaportal/Data/English/DocLibrary/2024115131527120/Issuing%20the%20Executive%20Regulation%20of%20the%20Personal%20Data%20Protection%20Law.pdf) تتناول الموافقة وحقوق صاحب البيانات وسجل المعالجة والاختراق ونقل البيانات خارج السلطنة.
- [قانون حماية البيانات الشخصية، المرسوم 6/2022](https://www.mtc.gov.om/itaportal/Data/English/DocLibrary/2024115132533256/PROMULGATING%20THE%20PERSONAL%20DATA%20PROTECTION%20LAW.pdf) هو الأساس التشريعي، ويحتاج تطبيقه على النشاط إلى مراجعة قانونية عُمانية.
- [دليل خدمات وزارة التجارة والصناعة وترويج الاستثمار](https://tejarah.gov.om/en/service-directory) يوضح أن منصة عُمان للأعمال هي قناة تأسيس الشركات والتراخيص والتقارير، ولا يعني ذلك وجود API مفتوح لخدماتي.

لا يدعي المشروع امتثالًا قانونيًا نهائيًا. السياسات مسودات تقنية تحتاج اعتماد كيان المشروع ومستشار قانوني قبل النشر التجاري.

## ما يمنع إعلان Production الآن

- لم يُثبت Persistent Database وObject Storage ونسخ احتياطي خارجي على Render.
- لا توجد مفاتيح دفع أو OTP أو Push إنتاجية معتمدة.
- لا يوجد اختبار اختراق بشري أو اختبار iPhone فعلي.
- لا توجد موافقة قانونية على التأمين أو التقارير الوطنية أو التكامل الحكومي.
- لا ينبغي إنشاء Tag أو GitHub Release أو نشر عام قبل إزالة هذه الحواجز.
