# جاهزية Apple App Store

**تاريخ التحقق:** 26 يوليو 2026
**الحالة:** 🟡 ملف تجهيز، وليس تأكيد قبول أو نشر

## النتيجة المختصرة

المشروع الحالي PWA يعمل من المتصفح ولا يحتوي مشروع Xcode أو ملف IPA أو Target
أصليًا. لذلك لا يمكن رفعه إلى App Store بصورته الحالية. يلزم أولًا قرار موثق
لإنشاء تطبيق iOS أصلي أو غلاف موثوق للويب، ثم اختبار وظائف الجهاز داخل الغلاف.

## ما هو جاهز

- اسم التطبيق: «خدماتي» و`Khadamati App`.
- واجهة عربية RTL وإنجليزية LTR.
- Manifest وأيقونات Web وApple Touch.
- تسجيل حساب وحذف حساب داخل الإعدادات.
- سياسات داخل التطبيق ومسودات مستقلة في مجلد الإطلاق.
- إذن الموقع عند الطلب، وإدخال المنطقة يدويًا كبديل.
- صور ومحادثات وصوت وإشعارات ويب، لكنها تحتاج اختبارًا أصليًا بعد التغليف.
- حساب زائر للوظائف العامة التي لا تتطلب حسابًا.

## موانع الرفع الحالية

1. لا يوجد مشروع iOS أو Bundle ID محجوز.
2. لا توجد شهادة Distribution أو Provisioning Profile.
3. لا يوجد Build موقع أو TestFlight.
4. لا يوجد رابط عام معتمد للخصوصية وحذف الحساب والدعم.
5. لا توجد بيانات كيان قانوني مكتملة أو مراجعة قانونية للسياسات.
6. لا توجد بيئة staging دائمة وحسابات مراجعة مستقرة.
7. استمرارية SQLite والملفات على Render غير مثبتة.
8. الدفع وOTP وPush ليست تكاملات إنتاجية مكتملة.
9. لم تُختبر الكاميرا والميكروفون والموقع والإشعارات على غلاف iOS فعلي.

## معرّف مقترح غير محجوز

```text
om.khadamati.app
```

🔴 يجب أن يحجزه مالك حساب Apple Developer بعد التأكد من ملكية الاسم والنطاق.
لا يُغيّر لاحقًا بلا أثر، فلا يُعتمد قبل القرار الرسمي.

## متطلبات المراجعة

- حساب مراجعة مستخدم ومزود وإدارة في staging، بلا بيانات حقيقية.
- تعليمات دقيقة لفتح الطلب والمحادثة وحذف الحساب.
- عدم ذكر «نسخة تجريبية» في المنتج العام؛ الاختبار الخارجي يكون عبر TestFlight.
- وصف وصور تطابق السلوك الفعلي ولا تعرض دفعًا أو إشعارات غير مفعلة.
- سياسة خصوصية متاحة داخل التطبيق وعبر URL عام.
- App Privacy يصرّح بالبيانات التي يجمعها التطبيق والشركاء الفعليون.
- إذا كان إنشاء الحساب متاحًا، يجب أن يستطيع المستخدم بدء حذف الحساب داخل
  التطبيق، لا الاكتفاء بتعطيله.
- توفير بديل يدوي عند رفض الموقع، وهو موجود منطقيًا ويحتاج اختبارًا في الغلاف.

## البيانات المتوقع التصريح بها

يُراجع هذا الجرد بعد اختيار SDKs الأصلية:

- الاسم ورقم الهاتف والصورة ومعرّفات الحساب.
- الموقع الدقيق عند الإذن، والمنطقة المختارة.
- صور الطلب وأعمال المزود ووثائق التحقق السرية.
- الطلبات والعروض والمواعيد والمحادثات والرسائل الصوتية.
- بيانات الاشتراك والمدفوعات الإدارية للمزود، دون بيانات بطاقة.
- رموز الجلسة ومحاولات الدخول واشتراك Push وسجلات الأمان.
- التشخيصات فقط إذا أضيفت أداة مراقبة لاحقًا.

لا تُملأ App Privacy قبل جرد SDK النهائي؛ الغلاف الأصلي قد يضيف جمعًا جديدًا.

## ما يجب أن يفعله المالك

1. إنشاء Apple Developer باسم المالك أو المؤسسة.
2. اعتماد الكيان والاسم التجاري والنطاق.
3. اختيار تقنية التطبيق الأصلي بعد تقييم فني.
4. حجز Bundle ID داخل حساب المالك.
5. توفير Mac وXcode وإدارة الشهادات داخل حساب المالك.
6. اعتماد السياسات قانونيًا ونشر روابطها.
7. اعتماد حسابات مراجعة staging.

> هذه الوثيقة قائمة جاهزية تقنية وليست ضمانًا لقبول Apple.
