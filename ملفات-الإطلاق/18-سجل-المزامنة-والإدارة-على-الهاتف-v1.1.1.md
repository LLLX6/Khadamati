# سجل المزامنة والإدارة على الهاتف — v1.1.1

التاريخ: 10 أغسطس 2026
الفرع: `release/production-readiness`
النطاق: إصلاح المطابقة والمزامنة والإشعارات والترجمة وتجربة الطلب والإدارة، دون نشر أو تعديل بيانات الإنتاج.

## ما تغير

- أزيل اعتماد الإنتاج على المزودين التجريبيين المدمجين في الواجهة؛ المزود الحقيقي يأتي من الخادم فقط.
- وُحّد عقد مطابقة الخدمات بين الواجهة والخادم، وأضيف تشخيص آمن لأسباب استبعاد المزود.
- أضيف إرسال إداري للطلب إلى مزود مؤهل دون قبول العرض أو تعيينه نيابة عن العميل.
- أضيفت دورة إدارة قابلة للاستعادة للمزود: نشط، موقوف، مؤرشف، ثم حذف مجهّل مؤكد.
- وُحّدت مزامنة الحساب والمحادثة ومنع تداخل طلبات التحديث، مع إبقاء الطلب المحلي المعلق عند ضعف الشبكة.
- أصبحت قراءة الرسائل والإشعارات أحادية الاتجاه؛ لا تعيد استجابة أقدم العداد بعد فتح المحادثة.
- أضيفت ترجمة إنجليزية لإرشادات الاستخدام والإشعارات، وتُعاد صياغة النافذة المفتوحة عند تغيير اللغة.
- بُسّطت صفحة تفاصيل الطلب، وأضيف البحث عن مزود معروف داخل التطبيق مع إبقاء قنوات الاتصال خلف الموافقة.
- أضيفت مؤشرات الإدارة: أسباب غياب المطابقة، الطلبات التي وصلها عرض، ومتوسط زمن أول عرض.
- أصبح تنقل الإدارة على الهاتف شريطاً ثابتاً أسفل الشاشة. صُححت قاعدة CSS قديمة كانت ترفعه إلى أعلى الصفحة وتحجب الأزرار.

## قرارات وحدود

- لم تُنشأ حسابات مزودين في الإنتاج، ولم تُستعد بيانات قديمة، ولم تُحذف أي بيانات.
- ظهور مزود حقيقي يتطلب حساباً محفوظاً في قاعدة الإنتاج، اعتماداً وتوفراً وخدمة ومنطقة مطابقة.
- إعداد Render الحالي يحتاج تخزيناً دائماً ومسارات إنتاج معتمدة حتى يعيد `/readyz` حالة `200`؛ التفاصيل في السجل رقم 16.
- أُذن لاحقاً برفع هذا النطاق إلى فرع `release/production-readiness`، وهو مصدر GitHub Pages. لا يشمل الإذن دمج `main` أو نشر API على Render أو تغيير خطة أو DNS أو بيانات إنتاج.
- ملفات `output/` و`tmp/` والوثيقتان 13 و14 كانت موجودة خارج نطاق هذه الدفعة ولم تُحذف أو تُضمّن تلقائياً.

## الإجراءات الخارجية

- رفع Commit الإصلاح إلى `release/production-readiness` ينشر الواجهة الثابتة عبر GitHub Pages.
- يبقى Render مرتبطاً بفرع `main`، لذلك لا يتغير API بهذه العملية.
